# 渠道活码前置能力建设计划（企业微信代开发 + 双向同步）

## 背景与目标

当前渠道活码能力已具备部分基础，但仍存在关键前置能力缺失：

1. 账号接入仍依赖人工代接与大量参数手填。
2. 企业微信标签与系统标签未完成双向同步。
3. 组织架构仅完成单向同步。
4. 外部联系人与线索仅完成单向同步。

因此，在继续推进渠道活码规模化前，需要先完成“接入简化 + 双向同步基础域”建设。

## 范围声明

本计划聚焦 4 个前置域：

1. 企业微信代开发接入改造。
2. 标签双向同步。
3. 组织架构双向同步。
4. 外部联系人与线索双向同步。

渠道活码功能本身在本阶段仅允许缺陷修复，不新增业务能力。

## 阶段计划

### Phase 0：冻结与门禁（1-2 天）

目标：建立统一前置门禁，避免活码功能超前开发。

工作项：

1. 冻结渠道活码新功能开发，仅保留缺陷修复。
2. 定义“前置能力完成门禁”清单。
3. 明确租户、企业、渠道账号关系模型（是否支持一租户多企业）。

验收：

1. 活码需求进入 `Blocked by Sync Foundation` 状态。
2. 门禁清单在评审中通过并归档。

### Phase 1：企业微信代开发接入（P0，1-2 周）

目标：降低客户接入复杂度，减少人工代接。

工作项：

1. 实现代开发授权链路（安装、授权、回调、续期）。
2. 建立 `tenant <-> corp <-> app(account)` 绑定关系。
3. 将“手填参数”改为“授权自动落库”。
4. 保留手动接入模式作为降级与存量兼容方案。
5. 增加接入状态页：授权状态、Token 状态、回调状态、最近同步时间。

验收：

1. 新客户可在不手填核心密钥参数的情况下完成接入。
2. 授权失效可观测并可触发重授权。

### Phase 2：标签双向同步（P0，1-2 周）

目标：打通企业微信标签与系统标签一致性。

工作项：

1. 完善本地标签模型：标签组、标签、映射关系、版本号。
2. 企业微信 -> 本地：全量初始化 + 增量事件同步。
3. 本地 -> 企业微信：创建、更新、删除回推。
4. 冲突策略：默认远端优先 + 本地冲突待处理队列。
5. 增加重试、幂等键、死信队列与人工重放。

验收：

1. 双向标签变更可在 SLA 内收敛一致。
2. 冲突、失败、重试过程可审计与可追踪。

### Phase 3：组织架构双向同步（P0，1-2 周）

目标：实现部门与成员双向一致。

工作项：

1. 标准化部门/成员/映射模型。
2. 先全量同步，再事件增量同步。
3. 支持本地变更回推（增删改、启停、调部门）。
4. 处理边界场景：离职、禁用、跨部门、多部门归属。

验收：

1. 组织树与成员状态双向一致。
2. 无重复成员、孤儿部门、失联映射。

### Phase 4：外部联系人与线索双向同步（P0，1-2 周）

目标：形成线索双向流转闭环。

工作项：

1. 外部联系人入池（企业微信 -> 系统线索）。
2. 线索关键字段受控回写（系统 -> 企业微信）。
3. 去重策略：`external_userid + 手机 + 企业 + 渠道`。
4. 状态与字段映射策略，避免覆盖人工关键信息。

验收：

1. 双向同步后无明显数据污染与回流错配。
2. 去重准确率与回写成功率达标。

### Phase 5：稳定性与运营能力（P0，1 周）

目标：保证可运营、可观测、可恢复。

工作项：

1. 建立同步任务中心：排队、重试、死信、手动重放。
2. 建立可观测面板：成功率、延迟、冲突数、失败 TopN。
3. 建立全链路回归测试矩阵。

验收：

1. 连续 7 天稳定运行，核心指标达标。
2. 关键链路告警与排障手册可用。

## 渠道活码重启门禁（必须全部满足）

1. 代开发接入可用，且无需客户手填核心参数。
2. 标签双向同步稳定。
3. 组织架构双向同步稳定。
4. 外部联系人与线索双向同步稳定。
5. 同步任务具备重试、审计、重放能力。

## 执行策略

1. 按 P0 基础域推进，活码功能仅做缺陷修复。
2. 每个阶段结束后进行门禁评审，通过后才进入下一阶段。
3. 对存量手工接入客户保留兼容路径，分批迁移到代开发模式。
