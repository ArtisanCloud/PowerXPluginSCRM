# DingTalk 渠道特性（扩展）

## 适配目标

- 复用通用同步框架，以最小改动接入钉钉渠道能力。
- 保持与 WeCom/Feishu 相同的任务中心、冲突处理与可观测标准。

## 首批建议范围

1. 授权接入与绑定关系。
2. 标签或分组等价能力双向同步。
3. 组织架构双向同步（部门/成员）。
4. 外部联系人与线索回写按渠道能力逐步开放。

## 约束与注意点

- 部分能力在钉钉侧可能无等价字段，需要策略降级。
- 事件与回调模型差异较大，需单独适配幂等键口径。
- 回写字段必须遵守“受保护字段不可覆盖”规则。

## 与通用层协作

- DingTalk 适配器对外暴露统一同步接口。
- 工厂按 `channel + app_type` 注册和解析具体实现。

## 能力矩阵（Phase 1 对齐）

| 能力域 | 状态 | capability_status | 说明 |
|---|---|---|---|
| 授权接入 | 规划中 | planned | 按统一授权契约接入 |
| 标签/分组双向 | 规划中 | planned | 以钉钉等价能力实现 |
| 组织双向 | 规划中 | planned | 部门/成员映射需先校准 |
| 外部联系人入池 | 待评估 | not_supported | 视渠道开放能力决定 |
| 线索回写 | 待评估 | not_supported | 受字段和权限模型影响 |
