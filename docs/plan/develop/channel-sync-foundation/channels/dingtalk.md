# DingTalk 渠道特性（扩展）

## 适配目标

- 复用通用同步框架，以最小改动接入钉钉渠道能力。
- 保持与 WeCom/Feishu 相同的任务中心、冲突处理与可观测标准。

## 首批建议范围

1. 授权接入与绑定关系。
2. 标签或分组等价能力双向同步。
3. 组织架构双向同步（部门/成员）。
4. 外部联系人与线索回写按渠道能力逐步开放。

## 约束与注意点

- 部分能力在钉钉侧可能无等价字段，需要策略降级。
- 事件与回调模型差异较大，需单独适配幂等键口径。
- 回写字段必须遵守“受保护字段不可覆盖”规则。

## 与通用层协作

- DingTalk 适配器对外暴露统一同步接口。
- 工厂按 `channel + app_type` 注册和解析具体实现。
