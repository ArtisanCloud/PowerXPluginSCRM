# UC-004 重试不重复写数据（幂等）

## 实现状态

- 状态：部分实现
- 与 004 关系：已实现 WeCom webhook 幂等键口径（`tenant + channel_account_uuid + external_event_id`）
- 当前缺口：尚未统一覆盖 Bot 命令入口与多渠道 provider

## 目标

渠道重复投递或网络重试时，SCRM 业务数据只写一次。

## 前置条件

1. 消息带稳定 `idempotency_key`。
2. 幂等存储可查询并原子写入。

## 输入样例

- 同一 webhook payload 连续发送两次（message_id 与 idempotency_key 相同）。

## 处理流程

1. 首次请求：正常处理并记录幂等结果。
2. 第二次请求：命中幂等记录，跳过业务写入。
3. 返回上次处理摘要或标准幂等命中响应。

## 成功判定

1. 核心业务表仅有一次写入。
2. 第二次请求响应时间明显短于首次。
3. 幂等命中有单独审计标识。

## 失败分支

1. 幂等存储不可用：降级为拒绝执行并告警（避免脏写）。
2. 幂等键缺失：按策略拒绝或走低可信处理链。

## 004 对齐约束

1. WeCom webhook 幂等键口径不可变更。
2. 扩展其他 channel 时，必须保持同等幂等可观测能力。
